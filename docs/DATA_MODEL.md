# Data model and local workflows

- **Client** belongs to an organization. Its nullable `apptivoId` distinguishes internal clients from Apptivo copies; `(organizationId, apptivoId)` remains unique for non-null IDs. `displayName` is the Meedo-owned name. Internal rows have null Apptivo IDs and customer names. Client lists for members include only clients with a visible project.
- **Project** belongs to an organization and may link to a client. An internal project has a null `apptivoId`. `displayName` overrides the source quote subject and work order number. `isClosed` labels and filters projects; it does not block tickets or timesheets. `isArchived` hides archived records and `archivedManually` records an admin archive. Every client link and archive/closed flag is Meedo-owned. `clientLocked` is retired and retained only for historical audits; no application behavior uses it.
- **ProjectMember** joins a project, organization and user, unique by project and user. Admins see all projects; other members see only their assigned projects. Existing projects with no members are visible only to admins.
- **Ticket** optionally belongs to a project and keeps `createdById` as the reporter, with the earliest CREATED activity used only for older null rows. Members may create tickets in their visible projects or without a project, and edit their own tickets.
- **TimesheetEntry** keeps a calendar work date. With `ticketId`, the project and description are snapshots of the ticket. Without a ticket, a trimmed free-text description is required and project is optional. Legacy `task` remains readable. Submitted entries are editable by admins and edits are audited. Period boundaries use calendar-day keys in Asia/Manila.
- **Attendance** is one row per employee and company-local day (first in, last out, billable hours) built from AttendanceEvent punches. Its status is derived on read, not stored, from the effective weekly schedule (employee, then team, then organization default). Without a resolved schedule the day is `no_schedule` when there is no punch and `present_unscheduled` once a first in exists; an unscheduled day never has late minutes. With a schedule, holidays and rest days keep their status even when worked, and working days grade as `present`, `late`, `absent` or `upcoming` (live view, shift not yet due). The admin board counts `present`, `late` and `present_unscheduled` as Present (Late is the subset), and puts `no_schedule`, rest days and holidays in Off. Its `scheduled` total excludes unscheduled time-ins. Punches trigger an `attendance.updated` server-sent event so open boards refetch without a reload.
- **Notification** belongs to an organization and recipient user, with type, content, in-app link, entity, optional actor, read timestamp and creation time. HTTP reads are recipient-scoped. The Socket.IO gateway authenticates the Better Auth cookie, joins only the server-selected user room, and emits new notifications and unread counts. The client reconnects without polling.

The Apptivo sync is **manual**. It adds previously unseen clients and projects. For existing sourced rows it refreshes only the Apptivo customer name, quote subject, quote reference and work-order number. It never changes display names, client links, status, total, reported date, memberships, closed state or archived state, and never archives or deletes rows. A missing record gets `missingFromApptivoAt` (the first absence date); reappearance clears this reference marker without restoring archived records. Empty responses are treated defensively as an incomplete import and do not mark records missing. Internal rows, including migrated seed records, have null source references and are never reconciled. Both manual import controls live in Settings, with administrator-only access and confirmation. Configure the work orders and customers resources separately with `APPTIVO_API_RESOURCE` and `APPTIVO_CUSTOMERS_API_RESOURCE`.

Production reverse proxies must forward WebSocket `Upgrade` and `Connection` headers to the API for Socket.IO. This is a deployment requirement; this document does not change proxy configuration.
